## Лабораторна робота 7: Звіти через LINQ to Objects

* **Домен:** Замовлення (`Order`, `OrderLine`, `OrderStatus`).
* **Звіти:** логіка винесена у `Core.Reports.ReportService`, результати повертаються у вигляді незмінних DTO-рекордів (`OrderReportLine`, `GroupSummary`, `OrderLineJoinDto`).

### Перелік запитів (ReportService)
1. `ExpensiveOrders(threshold)` — Які замовлення перевищують задану суму? Використані оператори: `Where`, `OrderBy`, `ThenBy`, `Select`.
2. `TopByTotal(n)` — Які N замовлень мають найбільший чек? Використані оператори: `OrderByDescending`, `ThenBy`, `Take`, `Select`.
3. `ByStatus()` — Як розподіляються замовлення та їх сумарна вартість за статусами? Використані оператори: `GroupBy`, `Select`, `OrderByDescending`, `Count`, `Sum`.
4. `Totals()` — Які загальні підсумкові показники замовлень? Використані оператори: `Sum`, `Average`, `Max`.
5. `JoinedOrderLines()` — *(Додаткове)* Зведення даних замовлень та їхніх рядків через `Join`.

### Відкладене виконання (Deferred Execution)
Запити у LINQ (як-от `Where`) описують умову, але не виконуються негайно. Обчислення відбувається лише під час перебирання результату (наприклад, виклику `Count()` або `ToList()`). У демо-коді перший виклик `query.Count()` проходить колекцію і повертає `4`. Потім ми додаємо нове замовлення до джерела. Оскільки запит відкладений, повторний виклик `query.Count()` знову проходить по колекції і бачить уже `5` елементів. Виклик `ToList()` фіксує результати у незалежний знімок, тому його `Count` не змінюється навіть після подальшого видалення елемента з джерела.

### Методний синтаксис (Method) vs Синтаксис запитів (Query)
У межах додаткового завдання №3 реалізовано метод `ByStatusQuerySyntax`. 
* **Методний синтаксис** (`source.GroupBy(...).Select(...)`) добре читається зліва направо, зручний для простих фільтрів і дозволяє легко додавати кастомні екстеншни. 
* **Синтаксис запитів** (`from ... group ... into ... select`) краще читається, коли запит має складні з'єднання (`Join`) або потребує багаторазового доступу до проміжних змінних групи. У домені замовлень групування за статусом виглядає інтуїтивно зрозуміліше саме в синтаксисі запитів через ключове слово `into`.

### Запуск (CLI команди)

Основні підкоманди звітів:
# 1. Топ-5 замовлень за сумою (з другим ключем сортування)
```
dotnet run --project src/Cli -- report-top
```
# 2. Замовлення від 15 000 грн (фільтрація)
```
dotnet run --project src/Cli -- report-high
```
# 3. Групування замовлень за статусом (кількість та сумарна вартість)
```
dotnet run --project src/Cli -- report-groups
```
# 4. Підсумкові агрегати (всього позицій, загальна сума, середнє, макс)
```
dotnet run --project src/Cli -- report-sum
```
# 5. Зведений звіт (Join) — з'єднання замовлень та їхніх рядків
```
dotnet run --project src/Cli -- report-join
```
# 6. Тест продуктивності — порівняння часу виконання на 100 000 записів із ToList та без нього
```
dotnet run --project src/Cli -- report-perf
```
